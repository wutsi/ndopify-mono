Build the Ndopify website in three stages, using the skills `neo-user-journey`, `power-design`, and `impeccable` in
sequence.

Output location: write all generated HTML (and any page-specific assets) under
`modules/ndopify-website/src/main/html/` — the existing
`modules/ndopify-website/src/main/html/assets/images/` directory already holds the checked-in logo/icon assets.

Prerequisite: `modules/ndopify-website/DESIGN.md` must exist (generated by the `init-website-design` skill). If it is
missing, stop and ask the user to run `init-website-design` first.

Language: all generated page content — copy, labels, microcopy, form field names, error/validation messages,
button text — must be in French. The source docs and the CTA strings below are all French; don't default to
English for anything not explicitly quoted in this file.

# Content Generation Sequence

## Stage 1 — Plan with neo-user-journey:

Create journey maps for the three audiences/flows before any HTML exists:

- **Locataire (tenant):** landing page → `rechercher.html` wizard → Pass activation. Map actions, touchpoints, and
  emotional state at each step, especially the valley around disclosing that an ID document is needed for the Mobile
  Money Pass.
- **Bailleur (landlord):** landing page → `louer.html` wizard → audit visit. Same mapping, with the emotional risk point
  being the ID/titre-de-propriété requirement.
- **Agent:** landing page → `joindre.html` wizard → KYC review. Same mapping around CNI/NIU disclosure.

For each wizard, run a synthetic persona walkthrough (Confused First-Timer, Distracted Mobile User, Skeptical Evaluator
at minimum) and flag any step where a persona would hesitate or abandon. Use that output to:

1. Decide step order per form — group by topic, push sensitive fields (ID, Mobile Money number) later, front-load
   low-commitment fields.
2. Write the upfront KYC-disclosure microcopy for each form intro (one line, stated before the form starts).
3. Write the confirmation-screen next-steps copy for each form.

**Output:** a per-form step spec (step N title + fields + required/optional) and the microcopy strings above. Hand this
spec to Stage 2 verbatim — don't re-derive it there.

## Stage 2 — Generate with power-design (website path):

Brand: use `modules/ndopify-website/DESIGN.md` as the token source instead of Firecrawl.

Scope: multi-page, self-contained HTML/CSS, light theme only via semantic tokens.

Generate:

- Marketing pages (index.html, bailleur.html, agent.html): hero + proof stats, trust/guarantee feature
  cards (max 4), "how it works" steps (max 4), pricing table, FAQ, one repeated primary CTA per page.
- Wizard pages (joindre.html, louer.html, rechercher.html): built exactly from Stage 1's step spec and microcopy — do
  not re-plan the flow here, just implement it. Apply web rule #19 precisely: step-N-of-M progress indicator with real
  aria-valuenow/aria-valuetext, one fieldset visible at a time, visible <label>s, inline on-blur validation.

Apply all 20 rules from principles/web-principles.md, with special attention to #18 (one <h1>, no skipped heading
levels — wizard step titles are <legend>s, not nested headings), #11 (WCAG AA contrast), and #5 (one
primary CTA per view).

## Stage 3 — Verify with impeccable critique, then fix:

Run the full dual-agent critique (design review + mechanical detector) against all the generated pages. For the three
wizard pages specifically, apply the "Form-heavy / wizard" persona set (Jordan, Sam, Casey) from impeccable's own
table — cross-check its findings against Stage 1's synthetic-persona results from neo-user-journey; a disagreement
between the two is worth surfacing, not silently resolving.

Treat every skipped-heading, low-contrast, and design-system-color/radius finding as a bug, since power-design's
rulebook already promised those wouldn't exist.

Fix everything found, then re-run impeccable detect to confirm a clean result. If it still finds issues, fix those
and re-run again — repeat until a detect pass comes back clean, up to 3 fix/re-detect cycles total. If issues
remain after the 3rd cycle, stop and report the remaining findings instead of looping further — treat a finding
that survives 3 fix attempts as a sign it may not be fixable without a source-doc or design-token change (e.g. a
contrast ratio baked into the brand's own primary color), not as something to keep forcing.

# Additional Instructions

- Each audience has a dedicated marketing page:
    - `index.html` for tenant (The home page is the landing page for tenants).
    - `bailleur.html` for landlord
    - `agent.html` for agent

- The content of the marketing page should be tailored to the audience's needs and concerns, highlighting the benefits
  of using Ndopify for their specific situation.

- Each marketing page is associated with exactly **one** CTA button that redirects to a wizard page
    - `index.html` has `Chercher un Logement Vérifié` that redirects to `rechercher.html`
    - `bailleur.html` has `Proposer mon bien` that redirects to `louer.html`
    - `agent.html` has `Rejoindre l'équipe` that redirects to `joindre.html`

- In marketing page, each section contains the CTA button at the end of the section.

- Alternate the background color of each section to create a visual separation between sections.

- For the sections "Garanties ..." and "Comment ça marche", the cards should be maxed to 4, and their content should be
  based on the information provided in the "Website content" source (see Content Sources).

- When generating the website, make sure to focus only on features of the Phase 1 (refer to pitch document) and avoid
  adding features from subsequent phases.

- For the wizard pages, respect the steps defined in the "Website content" source, and use the same conversational tone and
  style as in the document.

- The css files should be generated into `modules/ndopify-website/src/main/html/assets/css/` and the js files into
  `modules/ndopify-website/src/main/html/assets/js/`.
  The images should be placed in `modules/ndopify-website/src/main/html/assets/images/`.

- For the FAQ sections, use the questions provided in the pitch document. Answer based on the informations provided in
  the documents. Feel free to add additional questions if necessary, but make sure to answer them based on the
  information provided in the documents. The max number of questions should be 10.

- **IMPORTANT:** Before updating any file, you must backup the original file first (with extension `.bak.html`).
